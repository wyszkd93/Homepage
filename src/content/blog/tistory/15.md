## redo.log

![](/images/tistory/15/1.png)

ORACLE\_BASE 아래 oradata 디렉토리를 보면 redo.log 파일들이 있습니다. 이 파일들은 **Recovery 작업을 하기 위해 Oracle의 Background Process인 LGWR(Log Writer)가 수시로 입력해주고 있는 파일**입니다.

## Oracle Database

![](/images/tistory/15/2.png)

Oracle Database의 구조는 크게 3가지 구성요소를 갖고 있습니다.

> **1\. Control File**  
> DB의 물리적 구조에 대한 정보를 갖고 있습니다.  
> ex)
>
> ```
> /ORA11GE/a.dbf 100M
> /ORA11GE/b.dbf 500M
> ...
> /ORA11GE/redo01.log
> /ORA11GE/redo02.log
> ...
> ```
>
> **2\. DB File**  
> 실제 테이블의 데이터를 갖고 있습니다.  
>   
> **3\. Redo Log File**  
> Redo Log Buffer가 기록하는 모든 데이터베이스의 변경사항을 파일로 저장합니다.

이번 글에서는 Redo Log File이 어떻게 사용되는지 알아보겠습니다.

## LGWR(Log Writer)

![](/images/tistory/15/3.png)

**LGWR은 LOG BUFFER에 저장되는 데이터베이스의 변경사항을 로그파일로 기록**합니다. 그 로그 파일이 위에서 본 redo.log파일이고 계속 생성되는 것이 아니라 각 데이터베이스 서버마다 갯수가 다르지만 **기본 2개는 있어야**합니다. 지금 부터 각 파일을 그룹이라고 하겠습니다.

## Log Sequence Number

**각 그룹에는 순차적인 번호**가 있습니다. 이 번호는 LGWR 프로세스가 낮은 번호의 그룹을 사용하기 위해 사용되기도 하지만, Database Buffer Cache에 변경된 내용이 얼마나 DB File에 적용되었는지 확인하기 위한 번호이기도 합니다. 즉, 비정상적인 종료나 문제가 생겼을 경우 **회복하기 위한 용도**로 사용됩니다.

## Log Switch Event

![](/images/tistory/15/4.png)

계속해서 그룹1에 변경된 내용을 기록하면 언젠가는 기록할 공간이 부족하게될 시기가 옵니다. 이때 **Log Switch라는 이벤트가 발생**하는데, **다른 그룹으로 대상을 변경하여 기록**하는 것 입니다. Log Switch Event가 발생하면 Checkpoint Event라는 것이 발생합니다.

Checkpoint 이벤트가 발생하면서 사용하게되는 그룹의 Log Sequence Number를 이전에 사용하던 그룹의 번호보다 하나 높은 번호로 변경됩니다.

## Checkpoint Event

![](/images/tistory/15/5.png)

**Checkpoint Event는 DBC 메모리의 변경된 정보를 실제 물리 DB File에 적용하는 이벤트**입니다. 그럼 Checkpoint Event가 완료되면 redo log file는 어떻게 될까요? 이 질문을 하는 이유는 redo log file은 회복을 위해 사용되는데 만약 DBC와 DB File안에 있는 내용이 일치한다면 그룹1의 내용은 더 이상 필요 없는 내용이지 않을까요?

**Checkpoint가 전진** 되었기 때문에 더 이상 이전 내용은 필요 없게되버립니다. RPG게임을 하다가 저장하게 되면 저장한 시점으로의 데이터만 필요하지 더 이상 이전의 저장내용이 필요 없듯이, 없어도 되는 로그내용이 되버립니다.

## Log File Full

![](/images/tistory/15/6.png)

Checkpoint의 전진으로 더 이상 필요없게되버린 Group1의 내용을 위의 이미지에 이어서 생각해보겠습니다. 만약 group1을 전부 사용하고 Log Switch가 발생해서 Group2에다 기록하다가 **Group2까지 더 이상 기록할 공간이 없다면 어떻게 될까요?** 

Checkpoint Event가 발생해서 Log Switch Event가 다시 발생하고 **더 이상 필요없는 내용이 되어 버린 Group1에 Overwrite하여 기록**을 계속합니다.

그럼 **Log Switch를 하려고하는데 Checkpoint Event가 끝나지 않았을 경우 어떻게 될까요? 이런 경우에는 기다려야합니다.**

## Checkpoint 흐름

![](/images/tistory/15/7.png)

> **1\. Log Switch 발생 --> Checkpoint Event**  
> Log Switch 발생   
>   
> **2\. Checkpoint Event**  
> DBC 메모리의 변경 내용을 DB File에 적용하고 작업이 끝나면 CKPT에게 끝났다고 신호를 줍니다.  
>   
> **3\. Control File 기록**  
> Control File에 Checkpoint SCN을 기록합니다.  
>   
> **4\. DB File Header 기록**  
> 모든 DB File Header에 Checkpoint SCN 정보를 기록합니다.

Checkpoint 이벤트가 발생하면 위 흐름대로 계속 반복합니다. 그런데 만약 2번의 작업이 끝나지도 않았는데 Log Switch가 발생해서 다시 Checkpoint Event가 발생했고 그룹은 2개 밖에 없을때는 **이전 Checkpoint 작업이 끝날때까지 대기**해야합니다.
